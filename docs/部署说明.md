## 三、日常运维

```bash
bash ~/myproject/restart-bbs.sh     # 改了代码后重启
tail -f ~/myproject/logs/bbs.log    # 看日志
curl -s localhost:8009/healthz      # 健康检查，返回 ok 即正常
```

### 开机自启 + 掉线自愈（已配好，无需再动）

计划任务写在 `/etc/cron.d/xingzhibbs`（由 `install-cron-bbs.sh` 生成）：

```
@reboot      wza0126 bash /volume2/homes/wza0126/myproject/watchdog-bbs.sh >> .../logs/watchdog-bbs.log 2>&1
*/5 * * * *  wza0126 bash /volume2/homes/wza0126/myproject/watchdog-bbs.sh >> .../logs/watchdog-bbs.log 2>&1
```

由群晖自带的 `/usr/sbin/crond`（标准 vixie cron）读取，与 DSM「任务计划」的 `synoschedtask`
互不干扰，DSM 升级不会覆盖。

**为什么用户填 `wza0126` 而不是 `root`**：数据库和附件都在 wza0126 的家目录下，
以 root 跑会把这些文件写成 root 属主，之后用 wza0126 手动重启就会写不进去。
（校盘快传那边用的是 root + 全 777 目录，能跑但不干净，不必照抄。）

脚本是幂等的：服务活着就直接退出，挂了才拉起来。

实测记录（2026-09-11）：手动 kill 掉 8009 的进程，**16:25:01 整点刻度被自动拉起**，
日志留痕 `[2026-09-11 16:25:01] 检测到服务未运行，已自动启动 (PID 7446)`，健康检查随即 200。

### 改动上线前后各做一件事

```bash
# 1) 上线前先备份（WAL 模式下别直接复制 bbs.db）
cd ~/myproject/0/xgz-bbs && ~/myproject/venv/bin/python3 tools/backup_db.py --keep 30

# 2) 重启
bash ~/myproject/restart-bbs.sh
```

**验收请用 `tools/live_check.py`，不要用 `smoke_test.py`。**
冒烟测试会确认/打回真实的提交、调整真实的指派、在真实话题里发回复、还建测试账号 ——
库里一旦有老师们的真实内容，那些操作就是破坏。`live_check.py` 只做只读断言，
另外建一个**用完即删的临时账号**，把「建 → 改姓名/改登录账号/改学科 → 停用 → 启用 → 删除」
走一遍，最后核对账号总数没变：

```bash

BBS_SMOKE_BASE=http://192.168.10.201:8009 BBS_ADMIN_PASSWORD=<admin密码> \
  .venv/Scripts/python tools/live_check.py
```

## 五、备份

- **数据库**：SQLite 开了 WAL，直接复制 `bbs.db` 可能拿到不一致的快照（还会漏掉 `-wal` 里的最新事务）。
  用项目自带的脚本，它会 `VACUUM INTO` 出干净副本，**并立刻回读校验**：

  ```bash
  cd ~/myproject/0/xgz-bbs
  ~/myproject/venv/bin/python3 tools/backup_db.py --keep 30
  # 已备份 → data/backups/bbs-2026-09-14_1742.db  (148 KB)
  # 回读校验：users=8 topics=11 integrity_check=ok
  ```

  想自动化就挂个 DSM 计划任务，每天跑一次（`--keep` 顺便清旧备份）：

  ```bash
  cd /volume2/homes/wza0126/myproject/0/xgz-bbs && \
    /volume2/homes/wza0126/myproject/venv/bin/python3 tools/backup_db.py --keep 30
  ```
- **附件**：`data/uploads/` 直接整目录复制即可（都是 uuid 文件名，复制不会冲突）。
- 群晖自带的 **Hyper Backup** 可以把整个 `xgz-bbs/data` 目录纳入备份计划，
  建议一起做，异地副本才是真的保险。

## 六、排障

| 现象 | 处理 |
|---|---|
| 端口被占用 | `netstat -tlnp \| grep 8009`，确认不是别的服务；改 `restart-bbs.sh` 里的 PORT |
| 打不开页面 | 先 `curl localhost:8009/healthz`。返回 ok = 服务没问题，去查防火墙/端口 |
| 想换端口 | 改 `restart-bbs.sh` 和 `watchdog-bbs.sh` 里的 `PORT`，然后重启 |
| 忘记管理员密码 | `python3 tools/reset_admin.py`（本项目提供）或删库重来 |
| 附件占满空间 | 后台首页看「附件占用排行」，让对应课题组清理；或归档课题组 |
